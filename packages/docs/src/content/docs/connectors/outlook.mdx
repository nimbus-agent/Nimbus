title: Outlook
description: Index Outlook mail and read mail / calendar / contacts. Tools register conditionally on granted Microsoft Graph scopes.
---

The Outlook connector indexes mail messages — headers **and message bodies** — into the local SQLite index and exposes read tools across mail, calendar, and contacts, plus three HITL-gated write tools for sending mail and creating / deleting calendar events.

Tools are **registered conditionally** based on the granted Microsoft Graph scopes — if a tool's required scope is not in `MICROSOFT_OAUTH_SCOPES`, it is not registered and the agent cannot call it.

---

## What's indexed

- **Service id:** `outlook`
- **Item types:** `email` and `event` (sync indexes mail and your calendar; contacts are an MCP-only surface). Calendar events cover one day back to 30 days ahead and carry their start and end times; a connection made before Outlook requested `Calendars.Read` needs `nimbus connector auth outlook` again to index events.
- **Body:** the message body, up to **16,384 UTF-16 code units**. The sync `$select`s Graph's `body` alongside
  `bodyPreview`, converts HTML to plain text, and strips quoted reply chains and signature blocks.
  A message with no extractable body falls back to Graph's ~255-character `bodyPreview`, which stays
  searchable but is marked incomplete (`body_complete = 0`) rather than claiming to be the whole
  message.
- **Attachments are never fetched** — attachment bytes never reach the index.

Indexing depth is enforced on **every** sync, not just at `reindex` time. See
[Indexing depth](/user-guide/connectors/#indexing-depth).

## Authenticate

```bash
nimbus connector auth outlook
```

OAuth (Microsoft Graph). The Gateway resolves a short-lived access token via the Microsoft OAuth flow and injects it into the connector spawn as `MICROSOFT_OAUTH_ACCESS_TOKEN`. The granted scope set is also injected as `MICROSOFT_OAUTH_SCOPES` (space-separated) and gates which tools register at startup.

## Read tools (no HITL)

| Tool | Purpose |
|---|---|
| `outlook_calendar_get` | Get a single calendar event by id. |
| `outlook_calendar_list` | List calendar events in a time window (ISO 8601 `startDateTime` / `endDateTime`). |
| `outlook_contact_get` | Get a single contact by id. |
| `outlook_contact_list` | List contacts from the default folder. |
| `outlook_mail_folders` | List mail folders (pagination via `nextLink`). |
| `outlook_mail_list` | List mail messages (default folder `inbox` if `folderId` omitted). Pagination via `nextLink`. |
| `outlook_mail_read` | Read a single message (body, headers, attachments metadata). |

## Write tools (HITL-gated)

Every tool below requires interactive consent through the Gateway HITL gate before it executes.

| Tool | Purpose |
|---|---|
| `outlook_calendar_create` | Create a calendar event. |
| `outlook_calendar_delete` | Delete a calendar event. |
| `outlook_mail_send` | Send an email via Microsoft Graph. |

## Platform notes

- **Scope-gated tool registration.** Tools whose required Microsoft Graph scope is not in `MICROSOFT_OAUTH_SCOPES` are not registered at startup. Re-authenticate with broader scopes if you want more tools available.

**Remote content in a model-written draft is refused.** When the model (or an MCP client's proposal) saves an `outlook_draft_create` draft with `contentType` set to anything other than `text`, Nimbus reads the body as HTML and refuses it, before it asks you, if opening the draft would load remote content: an external image or tracking pixel, a CSS `url(` or `@import`, a `<link>`, `<iframe>`, `<base>` or `<meta http-equiv>`, an SVG image or `srcset`. An inline `cid:` image and plain links (`<a href>`) are allowed and shown to you verbatim. A draft sent as text is never scanned. The refusal is the same fixed message every time and repeats nothing from the draft.

**Remote content in a sent mail is refused.** An `outlook_mail_send` proposed by an MCP client (the model is never offered sends) is checked the same way at proposal and again when you accept it: with `contentType` set to anything other than `text`, a body that would load remote content when the recipient opens it is refused. The proposal's prompt shows every recipient (`to`, `cc`), the subject and the body exactly as they will be sent.
