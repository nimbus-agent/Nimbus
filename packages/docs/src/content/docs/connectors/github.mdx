The GitHub connector is the canonical first-party connector. It indexes pull requests and issues into the local SQLite index and exposes a wide read surface across repositories, PRs, issues, and Actions runs, plus a HITL-gated write surface for the operations on-call engineers reach for most: merging PRs, creating issues, deleting branches.

---

## What's indexed

- **Service id:** `github`
- **Item types:** `pr`, `issue`

## Authenticate

```bash
nimbus connector auth github
```

Stored in the Vault as `github.pat` and injected at spawn as `GITHUB_PAT`. Use a [fine-grained personal access token](https://github.com/settings/personal-access-tokens) scoped to the repositories you want indexed.

## GitHub Enterprise Server

To use a self-hosted GitHub Enterprise Server instead of github.com:

```bash
nimbus connector auth github --token <pat> --api-base https://ghe.example.com
```

A `gh` login on that host works too: `nimbus connector detect --source gh --host ghe.example.com`. Nimbus stores the instance as `github.api_base` and checks the token against it before saving anything.

- **Team credentials.** A team-vault entry for GitHub may carry its own optional `github.api_base` (leave it out for github.com). The team token is sent only to the host its own entry names, and a write's approval prompt shows that entry's instance, not yours. A team base that is present but invalid stops the write before any prompt.
- **Same name on two hosts.** With an Enterprise Server connected, a github.com checkout and an Enterprise repository with the same owner/name are one repository in the graph (ownership links only; no credential is affected).
- **One instance at a time.** A gateway talks to github.com or to one Enterprise Server, not both; connecting one stops syncing the other, and items already indexed from the previous instance stay until you run `nimbus connector remove github`. Re-run `connector auth github` without `--api-base` to go back to github.com.
- **https only.** The URL may be `https://host`, with an optional port and an optional `/api/v3`. A plain-`http` instance, a URL with a user, password, query or fragment, or any other path is refused, and so are `github.com` and `api.github.com` (omit the flag for those).
- **GHE.com is not supported.** GitHub Enterprise Cloud with data residency (`*.ghe.com`) uses a separate API host and is refused.
- **Which hosts are refused.** Loopback (`localhost`, `*.localhost`, `127.0.0.0/8`), unspecified (`0.0.0.0/8`) and link-local (`169.254.0.0/16`) addresses and IPv6 literals. Private addresses (RFC 1918) are allowed, because an appliance behind a VPN is the usual case. A literal check cannot stop DNS rebinding (a public name that resolves to a loopback address); your token goes only to the host you typed.
- **Fails closed.** If the stored value ever stops validating, the GitHub connector does not start and sends nothing, rather than falling back to github.com with your Enterprise token.
- **Redirects.** Every request Nimbus makes with your token follows only same-origin redirects (at most three); a redirect to another host or to `http` is refused.
- **What you see.** `nimbus connector status github` shows the instance host, and the approval prompt of a GitHub write shows an `Instance:` line.
- **Egress ledger.** A GitHub call is recorded as `github` whether it goes to github.com or to your instance; the instance is not in the ledger row.
- **GitHub Actions** shares this credential and instance. Job logs that your instance stores on a separate blob host may not download, because the sandbox only lists the instance and the github.com hosts.

## Read tools (no HITL)

| Tool | Purpose |
|---|---|
| `github_ci_run_get` | Get a single workflow run including jobs URL reference. |
| `github_ci_runs` | List GitHub Actions workflow runs for a repository. |
| `github_issue_get` | Get a single issue by number. |
| `github_issue_list` | List issues for a repository. |
| `github_pr_get` | Get a single pull request by number. |
| `github_pr_list` | List pull requests for a repository. |
| `github_repo_get` | Get repository metadata (owner/repo). |
| `github_repo_list` | List repositories the authenticated user owns or collaborates on. |

## Write tools (HITL-gated)

Every tool below requires interactive consent through the Gateway HITL gate before it executes.

| Tool | Purpose |
|---|---|
| `github_branch_delete` | Delete a branch by ref name. |
| `github_issue_create` | Create a new issue in a repository. |
| `github_pr_close` | Close a pull request without merging. |
| `github_pr_merge` | Merge a pull request. |
| `github_tag_create` | Create a lightweight tag pointing at a commit SHA. |

**Remote content in a model-written comment or issue is refused.** When the model (or an MCP client's proposal) writes a `github_issue_comment_create` comment or a `github_issue_create` body, Nimbus reads the text as Markdown and refuses it, before it asks you, if viewing it would load remote content: any Markdown image (`![alt](url)`, a reference image, an escaped or entity-spelled `!`), whatever its URL, even a relative upload; raw HTML that loads an external URL (`<img src>`, `<picture><source srcset>`, `<video>`, an `<iframe>`, a CSS `url(`); and a diagram block (`mermaid`, PlantUML, a Kroki type, `geojson`, `topojson`, `stl`) that names a URL. Plain links (`[text](url)`, a bare URL) are allowed and shown to you verbatim; a raw-HTML `<img>` with a relative `src` is allowed. Code blocks are not exempt, so some code is refused too: a Rust `#![allow(...)]`, code holding `url(`, `@import` or `src="https://`, an unclosed `<` followed by a letter (`if a <b`), an HTML snippet quoted in a code block. Describe the code or link to the file instead. The refusal is the same fixed message every time and repeats nothing from the text.

GitHub serves images through its own proxy, which hides your viewers' browser details, but a unique image URL still tells its owner that the comment was read and roughly when; Nimbus refuses it either way.
