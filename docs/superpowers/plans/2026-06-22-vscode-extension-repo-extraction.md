# VS Code Extension Repo Extraction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract `packages/vscode-extension` out of the Nimbus monorepo into a standalone public repo `nimbus-agent/nimbus-vscode` (cloned locally at `C:\gitrep\nimbus-vscode`), consuming `@nimbus-dev/client` as a published npm dependency, then remove the extension from the monorepo.

**Architecture:** The extension already talks to the Gateway IPC-only and its sole monorepo-internal import is `@nimbus-dev/client` (verified: 6 source files import it; nothing imports `packages/gateway` or `@nimbus-dev/sdk` directly). **BLOCKER fixed in Phase 0:** the currently-published `@nimbus-dev/client@0.2.3` ships an unrewritten `"@nimbus-dev/sdk": "workspace:*"` dep and is *not installable standalone* (`bun add @nimbus-dev/client@0.2.3` → `@nimbus-dev/sdk@workspace:* failed to resolve`); Phase 0 republishes a fixed `client@0.2.4` that pins the internal dep to concrete semver. With that done, extraction swaps `"@nimbus-dev/client": "workspace:*"` → `"^0.2.4"`, ports the existing CI/publish workflow into the new repo (dropping the monorepo-only "build client first" step), folds in the two safe hygiene fixes, and deletes the package + all references from the monorepo.

**Tech Stack:** Bun (toolchain), TypeScript 6.x strict, esbuild (bundler), Vitest (tests), Biome (lint), `@vscode/vsce` + `ovsx` (publish), GitHub Actions.

## Global Constraints

- **License:** MIT (extension), unchanged. `LICENSE` file ports verbatim.
- **Published dep pin:** `@nimbus-dev/client` must be `"^0.2.4"` (the Phase 0 fixed release) in the standalone repo — never `workspace:*` (that protocol only resolves inside the monorepo) and never `^0.2.3` (proven uninstallable standalone).
- **Client workspace-protocol fix is a standing requirement:** any future `@nimbus-dev/client` publish must rewrite internal `workspace:*` deps to concrete semver, or the standalone extension repo re-breaks. Phase 0 bakes this into `publish-client.yml`.
- **Do NOT copy build artifacts:** never copy `node_modules/`, `dist/`, or `media/webview.js` / `media/webview.css` (all generated). Use `git archive` so only tracked source ships.
- **Runtime self-containment:** `esbuild.mjs` bundles `@nimbus-dev/client` into `dist/extension.js` with only `vscode` external — so the client dep is build/typecheck-time only; the shipped `.vsix` has no npm runtime dependency on it.
- **Version bump:** the standalone repo's first release is `0.2.0` (the live Marketplace listing is `0.1.2`); the publish workflow stamps the package version from the git tag, so the in-repo `package.json` version is only the baseline. (Distinct from the Phase 0 *client* bump to `0.2.4` — do not conflate the two.)
- **Repo visibility:** `--public` (source already lives in the public monorepo; extension is MIT).
- **Action SHA pins:** every GitHub Action must be pinned by SHA with an accurate `# vX.Y.Z` comment. The `harden-runner`/`checkout`/`setup-node`/`upload-artifact`/`download-artifact`/`gh-release` SHAs below are copied verbatim from the monorepo's real `publish-vscode.yml`. The `oven-sh/setup-bun` SHA is NOT from an existing workflow and MUST be resolved before committing (see Task 7).
- **Two-repo change:** Phase 0 runs in `C:\gitrep\Nimbus` (client fix). Tasks 1–13 build/verify the new repo. Tasks 14–18 (monorepo removal) run on a **new branch in `C:\gitrep\Nimbus`**, NOT on `main`, and only after the new repo's CI is green.
- **Out of scope (future feature work, do NOT attempt here):** populating the status-bar `profile` / `degradedConnectorCount` (needs gateway connector-health queries not present in `client`); surfacing share/egress/federation/tribal/chatops; implementing a real Run-Workflow UI. This plan is extraction + the two safe hygiene fixes only.

**Interfaces:**

- [ ] **Step 1: Create `publish.yml`**

```yaml
name: Publish VS Code Extension

# Triggered by tags of the form `v0.2.0`. The tag version is written into
# package.json before packaging so Marketplace and Open VSX match the tag.
#
# Required repository secrets:
#   * VSCE_PAT — Azure DevOps PAT, "Marketplace (Manage)" scope, publisher `nimbus-agent`.
#   * OVSX_PAT — Open VSX token for the `nimbus-agent` namespace.

on:
  push:
    tags:
      - "v*"

permissions:
  contents: read

jobs:
  publish:
    name: Publish to VS Code Marketplace + Open VSX
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    environment: release
    permissions:
      contents: read
    outputs:
      version: ${{ steps.version.outputs.version }}
    steps:
      - name: Harden Runner
        uses: step-security/harden-runner@9af89fc71515a100421586dfdb3dc9c984fbf411 # v2.19.4
        with:
          egress-policy: audit

      - name: Checkout
        uses: actions/checkout@df4cb1c069e1874edd31b4311f1884172cec0e10 # v6.0.3
        with:
          persist-credentials: false

      - name: Setup Bun
        uses: oven-sh/setup-bun@<SETUP_BUN_SHA> # v2
        with:
          bun-version: latest

      - name: Setup Node (vsce/ovsx are Node CLIs)
        uses: actions/setup-node@48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e # v6.4.0
        with:
          node-version: "22"

      - name: Install
        run: bun install --frozen-lockfile

      - name: Typecheck
        run: bun run typecheck

      - name: Lint
        run: bun run lint

      - name: Test
        run: bun run test
        env:
          CI: "true"

      - name: Resolve version from tag
        id: version
        run: |
          tag="${GITHUB_REF_NAME#v}"
          if ! [[ "$tag" =~ ^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$ ]]; then
            echo "::error::tag '$GITHUB_REF_NAME' did not parse as semver after stripping 'v'"
            exit 1
          fi
          echo "version=$tag" >> "$GITHUB_OUTPUT"

      - name: Stamp package.json with the tag version
        run: npm pkg set version="${{ steps.version.outputs.version }}"

      - name: Build bundle
        run: bun run build

      - name: Package .vsix
        run: |
          mkdir -p dist-vsix
          bunx vsce package --no-dependencies --out dist-vsix/nimbus-${{ steps.version.outputs.version }}.vsix

      - name: Verify required publish secrets are present
        env:
          VSCE_PAT: ${{ secrets.VSCE_PAT }}
          OVSX_PAT: ${{ secrets.OVSX_PAT }}
        run: |
          if [ -z "$VSCE_PAT" ]; then
            echo "::error::VSCE_PAT secret is not configured."
            exit 1
          fi
          if [ -z "$OVSX_PAT" ]; then
            echo "::error::OVSX_PAT secret is not configured."
            exit 1
          fi

      - name: Publish to VS Code Marketplace
        env:
          VSCE_PAT: ${{ secrets.VSCE_PAT }}
        run: bunx vsce publish --pat "$VSCE_PAT" --no-dependencies --packagePath dist-vsix/nimbus-${{ steps.version.outputs.version }}.vsix
```
