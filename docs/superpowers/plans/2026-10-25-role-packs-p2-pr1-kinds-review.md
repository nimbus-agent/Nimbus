## 2. Implementation Traps & Suggested Refinements

### 2.1 ADR Query Placeholders with `sourceTypesOfKind("doc")`
In Task 2 Step 3:
```ts
// ADR query: replace the literal IN (...) with placeholders built from sourceTypesOfKind("doc")
```
- In PR 1, `sourceTypesOfKind("doc")` returns 3 elements (`["notion:page", "confluence:page", "obsidian:obsidian_note"]`).
- If `sourceTypesOfKind("doc")` were ever empty (e.g. in PR 2 if an active pack profile overrides all doc types), constructing:
  ```sql
  WHERE (service || ':' || type) IN (${placeholders})
  ```
  with an empty list would produce invalid SQL (`IN ()`), causing SQLite syntax errors.
- **Recommendation:** In `packages/gateway/src/decisions/decision-corroborate.ts`, guard the ADR query with:
  ```ts
  const docTypes = sourceTypesOfKind("doc");
  if (docTypes.length === 0) {
    // Return early or skip the ADR query branch
  }
  ```

### 2.2 `NEVER_EXEMPT_PATHS` Semantics in `exclusions.ts`
In Task 1 Step 4:
> Add `"packages/gateway/src/sources/source-kinds.ts"` to `NEVER_EXEMPT_PATHS` beside the two source-type files, with a one-line comment...

- **Codebase Context:**
  In [`scripts/coverage-floor/exclusions.ts`](file:///C:/gitrep/Nimbus/scripts/coverage-floor/exclusions.ts#L342-L373), `NEVER_EXEMPT_PATHS` is a list of carve-outs for files that would otherwise be excluded by the blanket `types.ts` / `-types.ts` regex in `EXCLUSIONS`.
- `source-kinds.ts` ends in `-kinds.ts`, **not** `-types.ts`. Therefore, it is **already NOT exempt** by default and is already gated by the coverage floor.
- **Trap:**
  [`scripts/coverage-floor/exclusions.test.ts:145`](file:///C:/gitrep/Nimbus/scripts/coverage-floor/exclusions.test.ts#L145) asserts `expect(existsSync(p)).toBe(true)` for every entry in `NEVER_EXEMPT_PATHS`.
  If Step 4 is executed before `source-kinds.ts` exists on disk, `exclusions.test.ts` will fail immediately.
- **Recommendation:**
  Ensure Step 3 (`source-kinds.ts` creation) is completed before editing `exclusions.ts`. Clarify in the comment in `exclusions.ts` that `source-kinds.ts` is explicitly listed to prevent future accidental exclusion if a `-kinds.ts` pattern is ever introduced.

### 2.3 Memoizing / Pre-computing Table Lookups
In Task 1 Interfaces:
```ts
export function sourceTypesFor(pass: SourcePass): readonly string[];
export function sourceTypesOfKind(kind: SourceKind): readonly string[];
```
- `sourceTypesOfKind("doc")` is called inside `corroborate()`, which executes per decision during extraction.
- In PR 1, `BUILTIN_SOURCE_KINDS` is immutable and known at module load time.
- **Recommendation:**
  Instead of re-filtering the map on every call to `sourceTypesOfKind` or `sourceTypesFor`, pre-populate read-only cached arrays at module load:
  ```ts
  const PASS_TYPES: Record<SourcePass, readonly string[]> = {
    decisions: Object.freeze([...BUILTIN_SOURCE_KINDS.entries()].filter(([_, k]) => PASS_KINDS.decisions.has(k)).map(([s]) => s)),
    glossary: Object.freeze([...BUILTIN_SOURCE_KINDS.entries()].filter(([_, k]) => PASS_KINDS.glossary.has(k)).map(([s]) => s)),
  };
  ```
  This eliminates array allocations inside hot decision loops.
