# `nimbus demo` — Zero-Config Try-It Path — Design

**Date:** 2026-06-18
**Status:** Design — pending user review
**Goal:** Let a brand-new user experience Nimbus's "wow" in under 2 minutes with **no accounts, no OAuth, and no LLM key** — so the first run matches the local-first pitch instead of contradicting it.
**Why:** The launch-readiness audit found the fastest current try-it path requires a cloud LLM key or a config edit. For a *local-first* product that's a credibility hole on day one. This closes Phase 0 blocker #2 of the launch plan.

## Problem

Today's first-value path needs: install → connect a real service (OAuth) → an LLM (cloud key or Ollama config) → ask. That's 4–5 steps and external dependencies before any payoff. A skeptic from HN/Reddit won't connect their real GitHub/Slack to evaluate an unknown tool.

## Goals / Non-goals

**Goals**
- One command, post-install, that shows a real cross-service query working: `nimbus demo`.
- No network calls, no credentials, no cloud LLM required.
- Reuses the real engine + real index path (not a faked screen) so what users see is what they'd get.

**Non-goals**
- Not a sandbox of the full product; it's a curated taste.
- No write/HITL actions in demo mode (read-only).
- Not a replacement for real onboarding — it ends by pointing at "connect your first real service."

## Approaches

**A. Bundled sample-data index (recommended).** Ship a small, pre-built read-only SQLite index fixture (synthetic PRs, incidents, deploys, a lineage chain) under the package. `nimbus demo` spins up the gateway pointed at this fixture in a temp/`demo` profile and runs a scripted query (or drops into an interactive prompt). *Pros:* deterministic, offline, instant, shows real ranking/search. *Cons:* needs a curated fixture + a way to point the gateway at it.

**B. Mock-connector live sync.** Reuse the E2E mock MCP servers to sync synthetic data into a throwaway index on the fly. *Pros:* exercises the sync path too. *Cons:* slower first run, more moving parts, the E2E mocks aren't a user-facing surface.

**C. Canned-answer demo.** Pure scripted Q&A with no real engine. *Rejected:* it's a fake; violates "what you see is what you get" and erodes trust if discovered.

**LLM in demo mode:** the query/answer step still needs a model. Two sub-options, ship both with auto-detect: (1) if Ollama is reachable on `127.0.0.1:11434`, use it; (2) otherwise fall back to a **retrieval-only** demo that shows ranked, correlated results + the structured brief *without* an LLM narrative — still impressive (the <100ms cross-service correlation is the wow), and truly zero-dependency.

**Recommendation:** **A + auto-detect LLM with retrieval-only fallback.** Deterministic, offline, honest, fast.

## Design (Approach A)

- **Fixture:** `packages/<demo-home>/fixtures/demo-index.sqlite` (or generated at first `demo` run from a checked-in seed script) containing a coherent scenario: an incident that ties a PagerDuty alert → a deploy → a PR → an author, plus a small lineage chain and a couple of repos for code search. Synthetic, clearly-fake names; **no real data, no secrets.**
- **Profile isolation:** `nimbus demo` uses a dedicated `demo` profile / temp data dir so it never touches the user's real index, Vault, or config. Tear-down leaves nothing behind (or a clearly-labelled `demo` profile they can delete).
- **Flow:**
  1. `nimbus demo` → prints a one-line "this is synthetic, offline, read-only" banner.
  2. Starts the gateway against the fixture in the `demo` profile.
  3. Runs 2–3 showcase queries (incident correlation, code/CVE search, lineage) and prints results; then drops into an interactive `ask` loop over the fixture.
  4. Detects Ollama; if absent, renders the structured brief + ranked correlation without LLM prose and says so.
  5. Ends with: "Liked it? Connect your real tools: `nimbus connector auth github --token …`".
- **Safety:** read-only; no connectors spawned; no outbound calls; HITL action types disabled in the demo profile.

## Open items to confirm against the codebase (before the plan)

- How a profile/data-dir override is passed to the gateway (there is profile support — `packages/cli/.../profiles`); confirm the exact flag/env to point at the fixture index.
- Whether the index schema fixture can be checked in as a `.sqlite` blob or must be generated by a seed script at runtime (migrations/version `V43` must match — generating via the real migration runner is safest).
- The retrieval-only render path (reuse `index.searchRanked` + the brief projection without invoking the LLM).
- Where the `demo` command + fixture should live (CLI command + a fixtures dir; mirror existing E2E fixture conventions).

## Acceptance criteria

- On a clean machine with **no** accounts, **no** keys, and **no** Ollama, `nimbus demo` shows real cross-service correlated results in <2 minutes and exits cleanly, touching nothing in the user's real profile.
- With Ollama present, the same command produces an LLM-narrated answer.
- The demo is unmistakably labelled synthetic and read-only; no network calls occur (verifiable).
- Documented as the first step in the install guide and linked from the README.
