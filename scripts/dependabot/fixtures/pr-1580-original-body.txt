Updates `jscpd` from 5.3.0 to 5.3.2
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/kucherenko/jscpd/releases">jscpd's releases</a>.</em></p>
<blockquote>
<h2>Release v5.3.2</h2>
<h3>New Features</h3>
<ul>
<li><strong>Rust dead code, read from the compiler.</strong> jscpd does not parse Rust, and does not need to. Every <code>cargo build</code> already prints lines like <code>function </code>reprint<code> is never used</code>, with real name resolution, trait dispatch and macro expansion behind them. The dead-code run now reads that output, from the JSON of <code>cargo check</code> (or <code>build</code>, <code>clippy</code>, <code>test --no-run</code>), and reports it next to everything else, through the same categories, reporters and <code>--min-confidence</code>, at 100% confidence.
<ul>
<li><code>basta</code> takes <code>--rust-diagnostics &lt;file&gt;</code>, or <code>-</code> for a pipe: <code>cargo check --all-targets --message-format=json | basta . --rust-diagnostics -</code>.</li>
<li>jscpd takes the same flag for <code>--dead-code</code>, <code>--dashboard</code> and <code>--health</code>, so a Rust project gets its health badge from the check it already runs: <code>cargo check --all-targets --message-format=json | jscpd . --health --rust-diagnostics - --reporters badge</code>. The dead-code section of the config file takes the file as <code>rustDiagnostics</code>.</li>
<li>Neither tool runs cargo itself, because that would execute the project's build scripts and procedural macros.</li>
<li>The compiler's span covers only the name, so the item's real size is read from the source. An item that <code>--all-targets</code> reports twice is counted once. A diagnostic inside a macro expansion, or for a crate outside the scanned paths, is left out.</li>
<li>A finding from a test target is handled like a test file in any other language: reported only with <code>--include-tests</code>, at 85%.</li>
<li>In a workspace, cargo writes paths relative to the workspace root, and they are resolved as such. A relative <code>manifest_path</code> in a hand-edited or copied file is resolved from where the file lives.</li>
<li>The compiler never reports a <code>pub</code> item of a library, and it has no notion of an unused file, so jscpd reports neither for Rust.</li>
<li>The dashboard's dead-code heading no longer names three languages, and a project with no language the run could read says so in its health score.</li>
<li>See <a href="https://github.com/kucherenko/jscpd/tree/HEAD/rust/jscpd/blob/fixtures/dead-code-demo/README.md#rust-from-the-compiler"><code>fixtures/dead-code-demo</code></a>. (<a href="https://redirect.github.com/kucherenko/jscpd/pull/1089">#1089</a>)</li>
</ul>
</li>
</ul>
<h3>Bug Fixes</h3>
<ul>
<li>
<p><strong>Text around an embedded code block was counted as code.</strong> A <code>ts</code> block in a markdown file, a <code>&lt;script&gt;</code> in a single-file component: jscpd scans these under the embedded language's own format, and the block keeps the line numbers of the file it lives in. The statistics read those numbers as if the block ran the whole way, which put the markdown prose and the component templates into the embedded language's line counts — both the total and the duplicated lines. On a repository with about 3600 markdown files the typescript row said 51.30% of lines were duplicated where the same code, scanned with <code>-f typescript</code>, said 3.37%. Neither number was a typo and both came from the same run.</p>
<p>An embedded source now counts the lines its blocks occupy, and a clone counts the block lines it covers rather than everything its fragment reaches across. The two percentage columns agree again, which is the quickest way to check a run: they measure the same duplication, so when the line column sits far below the token column it is counting text that holds no code. Ordinary files are counted exactly as before. See <a href="https://github.com/kucherenko/jscpd/tree/HEAD/rust/jscpd/blob/fixtures/embedded-stats-demo/README.md"><code>fixtures/embedded-stats-demo</code></a>. (<a href="https://redirect.github.com/kucherenko/jscpd/pull/1091">#1091</a>, closes <a href="https://redirect.github.com/kucherenko/jscpd/issues/1090">#1090</a>)</p>
</li>
<li>
<p><strong>Every clone was one line short.</strong> Duplicated lines came from <code>end - start</code>, so a clone covering lines 10 through 19 counted nine — while the console printed <code>10 lines</code> for it, from its own arithmetic. Line counts are inclusive now, and the header and the table come from one place. Expect duplicated-line totals to rise by about one line per clone, and percentages with them. (<a href="https://redirect.github.com/kucherenko/jscpd/pull/1091">#1091</a>)</p>
</li>
</ul>

<blockquote>
<h2>September 24, 2026</h2>
<h2>Highlights</h2>
<h3>Observability Capabilities Negotiation (Storage ↔ Server ↔ Client)</h3>
<p>Servers now expose <code>observabilityStorageCapabilities</code> (via <code>GET /system/packages</code> and the new <code>GET /observability/capabilities</code>) so Studio/clients can detect which observability APIs a configured store actually supports—covering per-endpoint discovery flags plus <code>traceQuery</code>, <code>threadQuery</code>, <code>deltaPolling</code>, and more—without forcing storage upgrades.</p>
<h3>Discovery-Backed Observability Filters &amp; Feature Declarations</h3>
<p>Observability stores can now declare supported features via <code>getFeatures()</code> (including entity/service/environment/tag/metric discovery), letting Studio only call compatible endpoints; VNext stores and Oracle now report discovery support, and discovery routes return empty results (not 500s) when unsupported.</p>
<h3>Trace Aggregation Planning API for Backends</h3>
<p><code>planTraceAggregate()</code> validates and converts an <code>aggregateTraces()</code> request into a <code>TrustedTraceAggregatePlan</code> that any storage backend can execute without re-validating, enabling consistent query behavior and clearer validation errors across storage implementations.</p>
<h3>Eager Tool Execution for Faster Streaming Runs</h3>
<p>Tool calls now start as soon as their own arguments are complete (instead of waiting for the model to finish streaming the whole step), cutting idle time in multi-tool steps; can be disabled per run (and is now supported in stored agent default options).</p>
<h3>New Integrations: Discord Channel + Sandbox Credential Materialization</h3>
<p>Added <code>@mastra/discord</code> to connect agents to Discord (slash commands, DMs, mentions, encrypted token-at-rest), and <code>@mastra/connect environment()</code> to materialize Platform connection credentials into <code>{ env, onStart }</code> for authenticated tooling inside sandbox providers (e2b/Modal/Daytona/Docker/subprocess).</p>
<h3>MongoDB Vector “Automated Embeddings” (Server-Side Embedding Generation)</h3>
<p><code>MongoDBVector</code> now supports Automated Embeddings: create an <code>autoEmbed</code> index (e.g. Voyage) and then write plain text + search with <code>queryText</code>, with MongoDB generating embeddings server-side (no embedding provider wiring or dimension bookkeeping in your app).</p>
<h3>Breaking Changes</h3>
<ul>
<li><code>@mastra/playground-ui</code> <code>TaskList</code> API: <code>title</code>, <code>TaskListHeader</code>, and <code>hideWhenEmpty</code> are removed.</li>

<p>An update endpoint response is not signed, and the signature only covers the downloaded artifact, so the announced <code>version</code> on its own does not prove which release the <code>url</code> and <code>signature</code> point at. minisign covers the trusted comment with its global signature, which lets the updater plugin compare the two and reject a response that pairs a version number with a different release. <p><code>tauri build</code> fills the version in automatically, and <code>tauri plugin add updater</code> now enables <code>requireSignedVersion</code> for the project it is adding the plugin to. <code>tauri signer sign</code> gains an <code>--app-version</code> flag for signing updater artifacts by hand, and warns when it is omitted.</p>
